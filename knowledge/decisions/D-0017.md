# D-0017: Optional Curios back equipment and input priority

Rusty requested Curios compatibility and selected **prefer the Curios back-slot bag**
when both back and chest routes contain Backpacks+ bags. This extends the previously
approved equipment design; it does not remove the native chest or hand-carried routes.

Use Curios 9.5.1's public item capability and inventory API, isolated behind a mod-presence
check. Tag all three tiers for the functional `back` slot and assign the preset back slot
to players through this mod's own data. This works without Sophisticated Backpacks. Do not
provide storage access from cosmetic slots or take over other mods' containers. If a data
pack adds several back slots, the first active Backpacks+ bag owns B and the gear bar.

All menu and mount operations resolve a server-owned source address: vanilla inventory
0..40, or functional back slot 41+i. A bound inventory still checks the exact stack object,
bag identity and revision on every edit. The native Curios capability refuses unequipping
an open bag; external removal, replacement or deactivation invalidates its menu. Curios
retains ownership of normal persistence and death/drop behavior.

Protocol 3 adds the worn source and cosmetic visibility to the authoritative snapshot.
Curios' render toggle hides the entire worn bag and its mounts, including reaching/opening
gestures. Storage, gear access and dynamic lighting remain functional: visibility is
cosmetic. An occupied cosmetic back slot also suppresses the functional bag render. No
duplicate Curios renderer is registered; the existing player layer renders once. Menus
and poses use the same source address, including late-tracker state.

Curios also defaults its inventory key to G. Preserve Rusty's approved hold-G gear gesture:
when an active bag is worn and both mappings use the same key/modifier, drain the competing
Curios-open click before its tick handler. Keep user bindings unchanged. A rebound Curios
key, its inventory button and no-bag input keep their native behavior. This uses normal
client key mappings and event priority, without mixing into or modifying Curios.

The gate uses the exact API version, real dedicated-server inventory tests, two clients,
native Curios menu clicks/toggles, real OS keyboard input, tracking/relog and a client/server
run with Curios absent. Release remains HELD. Sophisticated Backpacks migration and the
separate Quick Slot lighting integration remain independent release gates.

API references: [optional item capabilities](https://docs.illusivesoulworks.com/curios/items/curio-creation),
[player slot assignment](https://docs.illusivesoulworks.com/curios/slots/entity-register).
