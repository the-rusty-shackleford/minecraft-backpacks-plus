# D-0003: No nested storage containers; carry the held bag by its top strap

Accepted from Rusty's explicit instructions on 2026-09-17.

Backpacks must reject backpacks, chests and similar storage containers. The rule is
asymmetric: a backpack may be stored in a chest, but a chest may not be stored in a
backpack. Its purpose is to prevent compounded portable storage capacity. An empty
storage container is still a storage container; emptiness does not bypass admission.

The same server-owned admission rule must govern every implemented insertion route,
including direct clicks, shift-click, drag, number-key exchange and any exposed automation
interface. Do not rely only on a screen refusing an item. Modded containers need equivalent
handling; a vanilla-only list would leave the same capacity exploit open.

The exact boundary for utility blocks with inventories, such as furnaces, hoppers and
dispensers, is an interview question. No answer has been inferred. Existing legacy nested
contents must be preserved during conversion even though the new inventory rejects them;
the migration mechanism is still to be designed.

When selected in the hotbar and held, the player carries the backpack by its top strap,
with the bag hanging at the player's side. Treat this as its own held presentation,
including a hand-to-strap contact and appropriate bag orientation. Inspect both first-
and third-person views and moving poses. Do not use a generic block-holding transform
as the finished result.

The appearance/timing of opening the held bag is still being interviewed. This decision
does not resolve the outstanding visual style, tier appearance, mount-access or UI design.
