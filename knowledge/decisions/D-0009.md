# D-0009: Begin implementation and bring third-person animation review forward

Date: 2026-09-17. Status: accepted by Rusty's explicit "Start building" after the
persistent gear-bar prototype, followed by animation compatibility guidance.

This supersedes the interview-only implementation gate in D-0002. D-0001 through D-0008
remain the source of approved behavior. Build the reviewed direct-swap interaction,
first establishing item-safe server storage. Continue focused design discussion for
unresolved recipes and artwork without treating those as a hold on approved engineering.

Rusty wants early third-person previews of drawing/stowing mounted gear, taking the bag
off to open it, retrieving items and putting it back on. The first visual milestone
must show actual in-game motion, including another player's view, before final textures.
The held bag hangs from its top strap at the player's side. Preserve Refined Tools models.

Backpack action synchronization should carry semantic actions and their timing rather
than couple server inventory operations to a particular animation library. Rusty called
out Fresh Animations and preferred protocol-level compatibility. The actual personal
profile enables Fresh Animations 1.10.4 and FA Player Extension 1.1 through EMF 3.2.4/ETF
7.1, with Not Enough Animations 1.12.4, PlayerAnimator 2.0.4 and EMF Compat Core 1.1.2.
This inspection is not proof of runtime animation compatibility. The prior ranged-weapon
investigation found that FA's player pack can replace an unrecognized vanilla arm pose.
Investigate the installed EMF Compat Core source-priority/pose API; do not spoof a weapon
stance or modify the user's resource packs to make backpacks work.

Release remains held. Implementation authorization does not authorize production migration,
legacy mod removal, tags, pushes, releases, pack assembly or live server restarts.
