# D-0015: Mounted lights use the installed Luminance backend

Rusty requested that torches, lanterns and other light-producing attached items keep
emitting dynamic light from backpack mount slots. This implements the existing lighting
direction in the roadmap and original brief, with no new lighting engine or mixin.

The tested pack contains `luminance` 1.1.0 inside Vanilla Wheels 1.7.0; its nested
`neoforge.mods.toml` and source were checked. Use its existing interpolated entity-provider
API and `Providers.luminanceOf` lookup, including registered items, resource definitions,
block fallback and underwater behavior. The installed master, held-item and entity-provider
settings remain authoritative. This is an optional client-only integration; nothing loads
the adapter on a dedicated server or when Luminance is absent.

Only mounts on the equipped bag and bags held in either hand contribute. Ordinary storage
and backpacks carried inside the player inventory contribute nothing. Use the brightest
mount across these sources, at the same interpolated player light origin as held items.
Luminance combines light using maxima. If held light is already as bright or brighter,
the adapter adds no redundant source. Swapping uses current authoritative item locations,
not visual animation copies.

Cache dry/wet luminance for each bag's immutable contents component. A changed component
recomputes it, and resource reload clears the cache. Existing tracked equipment snapshots
supply remote players' mounted items; this requires no additional packet or server light.

The client gate compares actual backend sources, terrain light samples and dark-room
captures for local and remote players, including resource reload, water and shaders.
Original Quick Slot lighting remains a separate pending companion integration. Curios
routing is also pending; equipped-backpack light will follow that authoritative view
when the equipment route is implemented. Release remains HELD.
